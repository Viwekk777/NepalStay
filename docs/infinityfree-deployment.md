# InfinityFree automatic deployment

Status: prepared, not activated or tested against the hosting account.

The workflow builds on pull requests and pushes to main. Uploads run only on main and only when the repository Actions variable INFINITYFREE_DEPLOY_ENABLED is exactly true. No FTP credentials belong in source code.

## Confirm the live layout first

The workflow uploads the repository layout intact into FTP_SERVER_DIR:
- App/
- Public/ (including index.php)
- Views/
- JS/
- vendor/ (generated by Composer)
- root .htaccess and Composer files

Public/index.php expects vendor/ and .env one level above Public/. The current root .htaccess instead targets a root index.php, which is absent from this repository, and its rewrite expression also needs review. Do not enable deployment until the repository layout and rewrite rules match the working hosting layout. If the live site moves Public contents into htdocs directly, this workflow must be adjusted before activation.

Confirm that server-specific code edits on InfinityFree have been incorporated into GitHub; tracked files will be overwritten by deployment. Back up the existing application files before the first upload.

## Repository settings

Open Settings > Secrets and variables > Actions.

Add repository secrets:
- FTP_SERVER: FTP hostname from the NepalStay hosting account.
- FTP_USERNAME: FTP username for that same account.
- FTP_PASSWORD: FTP password entered directly into GitHub, never chat.
- FTP_SERVER_DIR: confirmed FTP path to the application root, ending with /. Do not guess this from the domain name or use the FTP account root.

Add repository variables:
- DEPLOY_PHP_VERSION: PHP major.minor version matching the hosting account. The build defaults to 8.3 until configured.
- INFINITYFREE_DEPLOY_ENABLED: leave unset until layout is confirmed; then set to true.

The connection uses explicit FTPS on port 21 with certificate verification. Confirm support in the hosting account. Investigate connection failures rather than disabling verification.

## First run

After correcting the layout if needed and merging into main:
1. Add the secrets and PHP version variable.
2. Confirm the existing production .env is in the application root with valid database and mail settings.
3. Set INFINITYFREE_DEPLOY_ENABLED to true.
4. Open Actions > Deploy NepalStay to InfinityFree > Run workflow on main.
5. Inspect build and upload logs, then test the homepage, assets, login, and booking pages.

Later pushes to main deploy automatically after build checks pass. Set the enable variable to false to pause uploads.

## Deployment boundaries

- Production .env files, SQL files, logs, editor metadata, docs, and Public/Assets/Uploads/ are excluded.
- Existing uploaded files and their .htaccess remain managed on the server.
- Database contents and schema are not deployed.
- Composer dependencies are generated from composer.lock with scripts and plugins disabled.
- The action tracks deployed files in .ftp-deploy-sync-state.json. Keep this state file; it enables incremental uploads. Previously deployed tracked files may be removed when removed from GitHub; unrelated server files are not cleaned.
- FTP uploads are not atomic. A failed transfer can leave a partially updated app. Rerun a failed upload after diagnosing it; rollback requires deploying a known good code version.
